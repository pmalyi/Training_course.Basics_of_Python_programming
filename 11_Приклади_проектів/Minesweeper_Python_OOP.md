### Загальна схема класів

Нижче наведено рекомендовану структуру класів. Ви можете додавати власні допоміжні методи/атрибути, але базова структура має зберігатися.

#### `enum Allocation` (файл `allocation.py` або `tile.py`)

Перелічення можливих станів клітинки:

```
class Allocation(Enum):
    HIDDEN
    REVEALED
    MINE
```

- `HIDDEN` — клітинка ще закрита;
- `REVEALED` — клітинка відкрита гравцем;
- `MINE` — клітинка містить міну (міни завжди закриті, доки не станеться вибух).

#### `class Tile` (файл `tile.py`)

Описує одну клітинку ігрового поля.

**Атрибути:**
- `state: Allocation` — поточний стан клітинки (за замовчуванням `HIDDEN`);
- `neighbour_mines: int` — кількість мін серед сусідніх клітинок (за замовчуванням `0`).

**Методи:**
- `__init__(self)` — ініціалізує клітинку зі станом `HIDDEN` та `neighbour_mines = 0`;
- `__repr__` / `__str__` (необов'язково) — для зручного відлагодження.

#### `class Board` (файл `board.py`)

Інкапсулює саме ігрове поле та всю логіку, пов'язану з ним. **Замість глобального масиву** використовуйте атрибут екземпляра класу.

**Атрибути:**
- `rows: int`, `cols: int` — розміри поля (наприклад, 12×12);
- `mines_count: int` — кількість мін;
- `grid: list[list[Tile]]` — двовимірний список об'єктів `Tile` розміром `rows × cols`;
- `hidden_count: int` — кількість ще не відкритих клітинок (потрібно для перевірки перемоги).

**Методи:**
- `__init__(self, rows: int, cols: int, mines_count: int)` — зберігає розміри, створює порожню сітку, викликає `initialize()`;
- `initialize(self) -> None` — виконує три кроки в такому порядку:
  1. заповнює всі клітинки об'єктами `Tile` зі станом `HIDDEN` і `neighbour_mines = 0`;
  2. розставляє міни у випадкових позиціях (`random.randint`), стежачи, щоб не переписати вже існуючу міну;
  3. для кожної клітинки обчислює й зберігає кількість мін серед сусідів, використовуючи допоміжний метод `_count_neighbours`.
- `_count_neighbours(self, x: int, y: int) -> int` — приватний допоміжний метод: розглядає до 8 сусідніх клітинок (менше — біля краю поля) і повертає кількість мін серед них;
- `display(self, debug: bool = False) -> None` — виводить поточний стан поля в консоль з індексами рядків зліва та індексами стовпців знизу. Символи:
  - `*` — закрита клітинка;
  - `.` — відкрита клітинка без мін поруч;
  - число — відкрита клітинка з відповідною кількістю мін поруч.

  Якщо `debug=True`, додатково позначає міни символом `X` (навіть якщо клітинка ще закрита) — це режим налагодження.
- `reveal(self, x: int, y: int) -> bool` — відкриває клітинку `(x, y)`. Повертає `False`, якщо на клітинці була міна (вибух), інакше `True`. Оновлює `hidden_count`;
- `_revealed_empty_neighbour(self, x: int, y: int) -> bool` — приватний допоміжний метод: перевіряє, чи має клітинка `(x, y)` серед сусідів вже відкриту клітинку з `neighbour_mines == 0`. Якщо так — повертає `True`;
- `check_neighbours(self) -> bool` — проходить по всьому полю та відкриває кожну закриту клітинку, для якої `_revealed_empty_neighbour` повертає `True`. Повертає `True`, якщо під час виклику було відкрито хоча б одну нову клітинку (тобто поле змінилося), інакше `False`;
- `is_won(self) -> bool` — допоміжний метод, що перевіряє умову перемоги (усі закриті клітинки — це міни).

#### `class Game` (файл `game.py`)

Керує ігровим циклом і взаємодією з користувачем.

**Атрибути:**
- `board: Board` — екземпляр ігрового поля;
- `is_running: bool` — прапорець стану гри.

**Методи:**
- `__init__(self, rows: int, cols: int, mines_count: int)` — створює `Board`;
- `get_user_move(self) -> tuple[int, int]` — запитує в користувача рядок і стовпець (з перевіркою коректності введення — не лише формату, а й діапазону значень);
- `play(self) -> None` — головний ігровий цикл:
  1. виводить поле (`display()`, у тому числі один раз у режимі debug на старті — за бажанням);
  2. у циклі: запитує хід гравця, викликає `reveal()`;
  3. якщо влучили в міну — виводить повідомлення про програш і завершує гру (`**** BOOOOM ****`);
  4. інакше — у циклі викликає `check_neighbours()`, доки поле не перестане змінюватися;
  5. перевіряє умову перемоги через `is_won()`;
  6. після кожного ходу виводить оновлене поле та кількість клітинок, що залишились закритими.

#### `main.py`

Точка входу в програму: створює екземпляр `Game` (наприклад, для поля 12×12 з 15–20 мінами) і викликає `play()`.

```python
from game import Game

if __name__ == "__main__":
    game = Game(rows=12, cols=12, mines_count=18)
    game.play()
```

## 1.4. Безпечні сусіди

Залишилась одна проблема: якщо гравець відкриває клітинку без жодної міни поруч, у класичному Сапері автоматично відкриваються й усі її сусіди (а якщо серед них теж є «порожні» клітинки — процес продовжується каскадно).

## 2. Додаткове завдання: графічний інтерфейс (GUI)

Останнім кроком перетворіть консольну гру на гру з **графічним інтерфейсом**, зберігаючи всю логіку в класах `Tile`, `Board` та `Game` (або в їх адаптованих версіях) — тобто ігрова логіка не повинна переписуватись «з нуля», лише замінюється спосіб взаємодії з користувачем.

Рекомендується використати бібліотеку **`tkinter`** (входить у стандартну бібліотеку Python), але можна також обрати `pygame` або будь-яку іншу GUI-бібліотеку на власний розсуд (за погодженням з викладачем).

### Вимоги до графічного інтерфейсу

- **Поле у вигляді сітки кнопок/клітинок**: кожна клітинка ігрового поля відображається як окремий елемент (наприклад, `tkinter.Button`) у сітці `rows × cols`.
- **Взаємодія мишею**: клацання лівою кнопкою миші по клітинці відкриває її (аналог `reveal(x, y)`); за бажанням — клацання правою кнопкою миші ставить/знімає прапорець (позначку підозрюваної міни).
- **Візуальне відображення станів**:
  - закрита клітинка — нейтральний колір (наприклад, сірий);
  - відкрита клітинка без мін поруч — інший колір (наприклад, білий), без тексту;
  - відкрита клітинка з мінами поруч — число, пофарбоване відповідно до кількості (класична схема Сапера: 1 — синій, 2 — зелений, 3 — червоний тощо);
  - клітинка з міною після програшу — окрема позначка (наприклад, 💣 або інший колір фону).
- **Каскадне відкриття сусідів**: під час натискання на клітинку без мін поруч інтерфейс має автоматично оновлювати вигляд усіх клітинок, відкритих завдяки `check_neighbours()`.
- **Індикація стану гри**: над полем або в заголовку вікна відображається лічильник мін/позначених клітинок, що залишились, а також повідомлення про перемогу чи програш (наприклад, спливаюче вікно `messagebox`).
- **Кнопка «Нова гра»**: дозволяє почати гру заново без перезапуску програми (повторний виклик `initialize()` на новому або тому самому об'єкті `Board`).
- **Розмір поля та кількість мін**: бажано зробити налаштовуваними (наприклад, через поля вводу або випадаючий список на старті гри), але допустимо залишити фіксованими (12×12, 15–20 мін), якщо це явно вказано в коді.

### Архітектурна порада

Створіть окремий клас, наприклад `GameGUI`, який:
- зберігає посилання на об'єкт `Board` (або `Game`);
- у конструкторі створює вікно та сітку кнопок відповідно до розмірів поля;
- має метод-обробник кліку (наприклад, `on_cell_click(x, y)`), що викликає логіку `Board`/`Game` і після цього перемальовує (оновлює) вигляд усіх клітинок;
- має метод `refresh(self)`, що синхронізує вигляд кнопок зі станом `board.grid` (кольори, текст, доступність натискання).

Таким чином, консольна версія (`display()` + `input()`) і GUI-версія (`GameGUI`) можуть використовувати той самий клас `Board` без дублювання ігрової логіки — це ключова перевага правильно спроєктованої об'єктно-орієнтованої архітектури.
